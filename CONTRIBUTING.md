# Contributing to Daena

Thank you for your interest in helping build the truth layer of the internet. This document covers org-wide contribution conventions. Each repository may add its own `CONTRIBUTING.md` with more specific guidance.

## Where to start

| If you want to... | Go to... |
|---|---|
| Discuss the protocol's design | [spec discussions](https://github.com/daena-protocol/spec/discussions) |
| Propose a substantive spec change | [DPIP proposals](https://github.com/daena-protocol/spec/tree/main/proposals) |
| Fix a typo or clarify wording | Open a PR on the relevant repo |
| Report a bug in the SDK or tooling | [daena issues](https://github.com/daena-protocol/daena/issues) |
| Contribute an example Daena document | [examples PRs](https://github.com/daena-protocol/examples/pulls) |
| Privately report a security issue | See [SECURITY.md](./SECURITY.md) |

## How we work

- All changes land via pull request. `main` is protected on every repo.
- At least one maintainer review is required before merge.
- Spec changes follow the [DPIP process](https://github.com/daena-protocol/spec/blob/main/GOVERNANCE.md).
- Commits should follow [Conventional Commits](https://www.conventionalcommits.org/) — e.g. `feat:`, `fix:`, `docs:`, `spec:`.
- Be kind. See the [Code of Conduct](./CODE_OF_CONDUCT.md).

## Licensing

- Source code — [Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0)
